LO QUE SE IMPLEMENTÓ EN ESTA SESIÓN
───────────────────────────────────────────────────────────────────

1. Sistema de autenticación para el dashboard
   - Tabla `usuario_sistema` en SQLite (id, username, password_hash,
     ig_user_id, ig_username, es_admin, creado_at)
   - Hash de contraseñas con bcrypt (fallback SHA256+salt si bcrypt
     no se puede importar)
   - Cookie de sesión "session" firmada con itsdangerous
     (URLSafeTimedSerializer), expira en 8 horas
   - SESSION_SECRET configurable vía .env

2. Endpoints nuevos en app/dashboard/router.py
   - GET  /login   → formulario HTML (estilo oscuro #0f0f0f / #00ff88)
   - POST /login   → valida con bcrypt, crea cookie, redirect /dashboard
   - GET  /logout  → borra cookie, redirect /login
   - GET  /dashboard → exige sesión válida
       * Si es_admin = 1  → ve TODAS las conversaciones
       * Si es_admin = 0  → filtra WHERE cuenta_monitoreada = ig_user_id
       * Header muestra "Bienvenido, @username" + badge ADMIN (si aplica)

3. Scripts nuevos / modificados
   - scripts/setup_usuarios.py     → crea los 4 usuarios iniciales
                                     (idempotente con INSERT OR IGNORE)
   - export_conversations.py       → parametrizado con argparse:
                                     --token, --ig-user-id,
                                     --app-scoped-id, --output-dir
   - scripts/import_conversations.py → parametrizado con --dir,
                                       usa app_scoped_id del JSON si
                                       está presente como cuenta_monitoreada

4. Dependencias agregadas a requirements.txt
   - bcrypt==5.0.0
   - itsdangerous==2.2.0
   - python-multipart==0.0.29   (necesario para Form() en FastAPI)

HALLAZGOS IMPORTANTES SOBRE META API
───────────────────────────────────────────────────────────────────

  - El IGSID que devuelve graph.instagram.com/me?fields=id NO es el
    mismo que el ID que aparece en los payloads de webhook.

    | Cuenta            | IGSID (/me)        | ID webhook         |
    |-------------------|--------------------|--------------------|
    | gimenezbenja2     | 26555696997406448  | 17841407634191670  |
    | hernestolopez2026 | (no verificado)    | 3227434987463112   |
    | fliagimenez2026   | 26628591963436168  | (sin verificar)    |

  - Por eso `usuario_sistema.ig_user_id` debe guardar el ID DEL WEBHOOK,
    no el IGSID. Si se confunde, el filtro no matchea.
  - Importante: cuando se haga export histórico de otra cuenta,
    usar --app-scoped-id con el ID del webhook (ese se persiste en
    los JSON y el import lo usa como cuenta_monitoreada).
